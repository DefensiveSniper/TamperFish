### ddd(领域驱动设计)
闲鱼（im）界面是领域 A 和 千牛（领域 B），可以看作两个独立领域，彼此不知对方存在。

那么跨领域的协调和查询，就由顶层的编排器AGENT（核心中枢） 负责。编排器负责同时下发任务给两个 Agent 。两个 Agnet 处理完任务后，写完 DB 后将结果返回回去。顶上的编排器 Agent 再呈现出一个结果给用户（用户请求在交互层）。

领域驱动的好处：
1. 就是可以独立部署，有的用户只做 A，有的用户只做 B，有的两个都需要的情况下我们各取所好 
2. A 和 B 实际上是不同的语义，管理闲鱼的时候是聊天，是提供做交易。而管理物流的时候实际上是完全另一套规则。因此可以完全按照板块的业务需要去任意发挥而不用担心两者之间会相互污染。符合“高内聚，低耦合“，这样好处是往后可以用少量的成本就增加一个新的业务领域而不影响现有 agent 的表现，且与此同时表结构隔离

综上，ddd 是未来拓展升级的核心
